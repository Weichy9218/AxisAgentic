skill 到底有没有用

S2 共 200 题 · gpt-5.6-sol · serper · 三道门 · 两臂只差 agent.skill_file 一个键

skill 被读了也被执行了：查询里含 URL 或路径的从 283 次降到 3 次。 但分数没动，+0.0046，95% 区间 [-0.0295, +0.0387]。 机制查清楚了，不是噪声：skill 修的那类错误，harness 的 site: 梯子已经以 96.6% 的成功率自动兜住了， 真正被消灭的失败每题只有 0.22 次。
这一轮最有价值的发现不在 skill 上。数值题里， 照抄「信息截止日之前最后一个公布值」的朴素做法得 0.7190 分，模型自己答得 0.4429 分， 配对差 +0.2761，95% 区间 [+0.1391, +0.4131]，不跨 0。 折算到 200 题总分上是 +0.0649，远超这批题量的噪声底 ±0.034。

01实验设计

S1 是蒸馏 skill 用的 200 题，S2 是重抽的另外 200 题，两者交集为 0，分层相同。 两臂跑同一批 S2、同一份 config、同一个模型，只差 agent.skill_file。 落盘可验：对照臂 system_prompt.txt 2,276 字节不含 skill 块，skill 臂 6,497 字节含。 两臂各 200/200 记分，零剔除，blocked_judge_unavailable = 0。

skill 由我（Claude）读 S1 轨迹后一次写成，没有跑 SkillOpt-Lite 的循环。 SkillOpt-Lite 默认 10 轮，每轮有 val gate 决定接受或回滚；这里是它的第一轮 improve，没有 gate。

04为什么行为变了分数没变

对照臂里 site: 梯子触发 178 次。这些查询在触发前已经返空，触发后绝大多数拿到了结果： 最终仍为空的只剩 80 次，占搜索的 5.4%。 也就是说 skill 阻止模型写的那些坏查询，在对照臂里本来就会被 harness 自动改写并拿到结果。 skill 省下的是额外的 HTTP 请求，不是失败。

两臂真实失败的差是 80 − 37 = 43 次，摊到 199 题上是每题 0.22 次。一个每题少犯 0.2 次、而且这类错误有 96.6% 会被自动兜住的改进， 不可能移动分数。机制到此完全解释，不需要归因到噪声。

05记分规则的不对称，会影响以后所有这类实验

按答案有没有翻转做无偏拆分（不用反事实，因为反事实里的概率和正确性相关，会系统性低估收益）：

分组题数对总分的贡献每题平均
答案没变（纯置信度效应）128 -0.0029—
捡回（错→对）16 +0.0357+0.3417
丢掉（对→错）9 -0.0295-0.5013

丢一题的代价比捡一题的收益大 47%。 原因是结构性的：模型答对时平均置信度 0.726，答错时 0.561。 把一个自信答对的翻成错，损失远大于把一个不自信答错的翻成对。 所以净答对题数不是分数的好代理，捡回和丢掉的比例要到约 1.5 比 1 才打平。

07v2 依据

基于以上，skills/forecast_v2.md 相对 v1 的改动：

  • 数值题改成锚点优先。先写下 T_cut 前最后一个公布值，把它当答案；要偏离必须给出可命名、可定日期的理由，且幅度小于一次典型的发布间波动。这是本页里唯一有明确、区间不跨 0 的证据支持的规则。
  • 加量纲核对。写完数字和锚点比数量级，差两倍以上就是换算错了。
  • 「同一站点两次失败换源」换成「绝不重复抓同一个 URL」。原规则实测反向，真实形态是重复抓取而不是换站点。
  • 加一条实时行情端点的说明。回测下它返回的是今天的数字，会被边界挡掉，要找同源的历史形式。
  • 压缩搜索那一节。它瞄准的问题 harness 已经修了，留两行保留省请求的收益，把 token 让给数值题。
  • 置信度那一条补上不对称性。证据扎实时不要因为一个晚到的弱信号推翻已有答案。

08这一页控制不了什么

没有验证集。v1 到 v2 的改动依据是我对 S2 轨迹的分析，不是一次 gate 过的实验。 SkillOpt-Lite 的循环每轮都在 val 上判定接受或回滚；这里没有，所以 v2 可能比 v1 差而我们暂时不知道。 要补上，需要第三批题 S3 做测试，S2 退化为验证集。

锚点基线用的是数据集自带的真实序列，模型必须自己找到它。 所以 0.7190 是这条规则的上界，不是模型照做就能拿到的分。它仍然要正确识别序列、读对字段和单位。

200 题的配对标准误约 0.017，能分辨的最小差约 0.034。 两次独立的配对对比（harness 修复、skill）翻转率都是 16.3%，这是当前噪声底的最好估计。
